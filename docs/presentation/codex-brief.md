# Codex 브리프 — Layer 2 데모+발표 통합 스크립트

> **이 문서의 목적**: 코딩/문서 에이전트(Codex)가 이 한 장을 읽고 **"발표 + 라이브 데모"가 하나로 엮인 통합 진행 스크립트**를 써낼 수 있도록, 필요한 재료를 전부 모아둔 핸드오프 문서다.
> Codex는 이 브리프를 **소스(재료)** 로만 쓰고, 산출물은 아래 §1의 형식으로 새로 작성한다. 본 문서를 그대로 복사하지 말 것.

---

## 0. 한눈에 (TL;DR for Codex)

- **만들 것**: Layer 2를 청중 앞에서 시연하며 설명하는 **통합 스크립트** — "지금 화면에서 뭘 누르고(데모) / 무슨 말을 하고(발표) / 무엇을 강조하는지(포인트)"가 한 줄 흐름으로 이어진다.
- **강조 균형**: ① 서비스·UX(왜 이 제품인가) ② 기술(어려운 문제를 어떻게 풀었나) ③ 사고의 흐름(어떻게 여기까지 왔나) — **셋을 균형 있게**.
- **길이**: 미정 → **모듈식**으로 작성. 각 비트(beat)에 `[핵심]`/`[선택]` 태그를 달아, 핵심만 추리면 ~5분, 다 풀면 ~15분이 되도록.
- **언어**: 한국어. 청중은 비전문가도 포함된다고 가정(전문 용어는 한 번 풀어서 설명).
- **정확성 원칙**: 코드에 실제로 있는 동작만 시연/주장한다. 과장 금지(특히 "마찰 계수"는 절대값이 아니라 **문서 내부 상대값**임을 흐리지 말 것 — §5 정직성).

## 1. 산출물 형식 (Codex가 출력할 것)

다음 3부 구조로 작성한다.

1. **오프닝(엘리베이터 피치)** — 30초. "Layer 2 = 나를 아는 독서" 한 문장 + 왜 필요한지 1~2문장.
2. **본문 = 비트(beat) 테이블** — 데모와 발표가 한 행으로 묶인 표. 각 행:

   | # | 구간/시간 | 화면 동작(클릭·데모 명령) | 발표 멘트(요지) | 강조축 |
   |---|---|---|---|---|
   | 예) 3 | ~1:30 `[핵심]` | 상단 **데모** 버튼 클릭 → 막힌 단락에 촛불 점등 | "사용자가 한 단락을 자꾸 되돌아 읽으면…" | UX+기술 |

   - `강조축`은 `UX` / `기술` / `사고흐름` 중 하나 이상.
   - 각 비트에 `[핵심]` 또는 `[선택]` 태그.
3. **클로징** — 30초. 한계의 정직한 인정 1문장 + 다음 단계(Phase 3) 1문장 + 마무리 한 줄.

추가로 맨 끝에 **"길이 조절 가이드"** 한 단락: 5분 버전(=`[핵심]`만), 10분, 15분(=전부) 각각 어떤 비트를 포함/제외하는지 표로.

## 2. 데모 안무 — 실제 화면 동작 레퍼런스 (정확히 이대로 동작함)

> 출처 코드: `demo.js`, `index.html`, `candle.js`, `viewer-shell.js`, `sources/surface-tension.js`

### 2.1 진입점 / 컨트롤
- **상단 우측 `데모` 버튼**(`#demo-run`, 아이콘 ▶, 라벨 "데모"): 현재 열린 글 위로 **한 번의 독서 세션을 시간순 재생**한다. 단락을 따라 스크롤하며 신호를 흘려, **촛불·티키타카가 자연 발동**한다. 코드 한 줄, DevTools 없이 발표 중 클릭만으로 시연 가능.
- **`데모 리셋` 버튼**(`#demo-reset`, ↺): 신호 비우고 새로고침.
- **DevTools 보조 명령**(필요 시): `window.__layer2Demo.seed()` 즉시 시드 / `.play()` 시간순 재생 / `.seedSessions(8)` 과거 세션 8개 시드(멀티세션 대시보드 채우기) / `.clear()` 초기화.
- **레이아웃 토글**(상단): `스크롤` / `스프레드` / `보드`(`view-toggle`, data-mode=scroll|spread|board).
- **좌측 레일**: 하이라이트 색상(`#hl-tool`), 독서 모드(`#reading-mode`, 안경 아이콘 = 포인터락 몰입 읽기).
- **우측 레일**: 북마크, 캡쳐, **기록/대시보드**(`#btn-records`).
- **데모 글**: `sources/surface-tension.js` — "표면장력" 글(개념적으로 묵직한 글 = Layer 2 타깃에 부합).

### 2.2 데모가 단락별로 만드는 인지 상태 (`demo.js`의 `roleFor`)
재생 시 단락마다 **다른 독서 패턴**을 심어, 마찰·ICAP·촛불·보드 색이 한 번에 채워진다:

| 단락 | 역할 | 남기는 신호 | 결과로 보이는 것 |
|---|---|---|---|
| 1번 | `deep` | 긴 체류 + 정교한 하이라이트 + **사려깊은 주석** + AI 대화 | 주석 직후 **촛불(annotation_seam)** → **티키타카** 대화, ICAP **C→I** |
| 2번 | `stuck` | 9.8초 체류 + **3회 되돌아 진입** + 역방향 + 무흔적 | **촛불(isolation_seam)** "여기 자꾸 되돌아오네…", load=extraneous |
| 4번 | `highlight` | 핵심 밑줄 | ICAP **A**(Active), 보드 흔적카드 |
| 5번 | `circle` | 동그라미 제스처 | ICAP **A**, 보드 흔적카드 |
| 처음·끝(~12%/86%) | `scan` | 짧은 훑기 | ICAP **P**(Passive), 낮은 마찰 |
| 그 외 | `normal` | 유창한 읽기 | 중간 |

### 2.3 권장 데모 동선 (Codex가 비트로 풀 것)
1. **표면장력 글 열기**(사이드바) → 평범한 리더처럼 보임.
2. (선택) `seedSessions(8)` 으로 과거 세션 시드 → 나중에 대시보드용.
3. **`데모` 버튼 클릭** → 자동 스크롤 + 신호 재생.
4. **2번 단락에서 촛불 점등**(막힘 감지) → "되돌아 읽음"을 시스템이 알아챔을 강조(UX+기술).
5. **1번 단락 주석 직후 촛불 → 💬 클릭 → 티키타카**(소크라테스식, 답이 아니라 질문) 시연.
6. **보드 모드로 전환** → 같은 글이 **흔적 카드 + 마찰 색**으로 재구성됨(움직임 2: 나를 알기).
7. (선택) **보드에서 🧠 회상 / "내 말 요약"** — 하이라이트가 빈칸 회상카드/1인칭 요약으로 변환(내재화).
8. **기록/대시보드 열기**(`#btn-records`) → **멀티세션 매크로 리포트**: 시간대별 리듬·마찰 추세·관심 토픽 칩.
9. **클로징**: 마찰은 상대값이라는 한계 + Phase 3(동기화/배치 AI).

## 3. 재료 A — 서비스·컨셉·UX (강조축: UX / 사고흐름)

- **미션 한 문장**: **"나를 아는 독서"** (Reading That Knows You).
- **문제 정의 / 차별점**: Readwise가 "깊은 몰입(deep flow)"을 돕는다면, Layer 2는 **① 다회독 시 인지적 마찰 감소** + **② 메타인지 리포트**(내 읽기 패턴을 시간에 걸쳐 드러냄)에 집중.
- **타깃 입력**: 가벼운 소설/뉴스가 아니라 **개념적으로 어려운 묵직한 글**(논문·철학·롱폼 에세이).
- **페르소나 가설(2026-05-27 확정, 06-02 검증)**: *"독자는 자기 독서 패턴을 발견하기 위해 시스템의 능동적 개입(AI 촛불)을 원하고 환영한다."*
- **두 개의 움직임(축)**:
  - **움직임 1 — 텍스트를 알기(내재화)**: 어려운 개념에서 맴돌면 시스템이 능동적으로 돕는다.
  - **움직임 2 — 나를 알기(메타인지)**: "당신은 저녁에 가장 깊게 읽는다" 같은 자기 발견.
- **세 개의 내러티브 아교(joints)** — 제품 일관성의 핵심 3축, 모두 구현됨:
  1. **뷰어 모드 전환**(스크롤/스프레드/보드)
  2. **촛불(Candle) AI 개입**
  3. **티키타카(AI 대화)**
- **기능 맵**:
  - 움직임 1: 촛불(이음새 타기) · 티키타카(소크라테스식 대화) · 회상(빈칸 클로즈 카드) · "내 말 요약"(편집형 1인칭 요약) · 인라인 자기설명 프롬프트.
  - 움직임 2: 보드 모드(흔적 전개·마찰 색) · 마찰 계수 · 멀티세션 매크로 리포트(시간대 리듬/마찰 추세/관심 칩) · ICAP 태깅 · 주의 블러(집중 이탈 표시).

## 4. 재료 B — 기술: 어려운 문제 → 영리한 해법 (강조축: 기술)

> 핵심 메시지: **"눈동자 추적 같은 계측 장비 없이, 브라우저 행동만으로 읽기 인지를 추론하고 실시간으로 교육적으로 반응한다."** 아래에서 발표 길이에 맞게 3~6개를 골라 쓸 것.

1. **가시성 가중 체류(visible_frac)** — 단순 체류 시간은 "읽는 중"과 "딴짓"을 구분 못 함. `IntersectionObserver`로 단락이 화면에 실제로 보인 비율을 가중 → 화면 밖 멈춤 노이즈 제거(계측 장비 0). *근거: Grusky 2017 뷰포트 주의.*
2. **되돌아 읽기 감지(reverse_rate)** — 스크롤 방향을 공짜 신호로 써서, 단락 재진입 시 역방향 비율을 0~1로 정규화 → 인지적 머뭇거림(재독·혼란)을 눈동자 없이 포착.
3. **동그라미 제스처 = 타원 기하 판정** — ML 없이 순수 기하(반지름·각도 커버리지 300°·원형성 임계 0.35)로 의도된 동그라미와 마우스 떨림을 구분. 텍스트 레이아웃에 맞춰 완전한 원이 아닌 **타원**으로 히트테스트.
4. **마찰 계수 = 다신호 z-점수 융합** — 체류·재방문·되돌아간 거리·역방향, 4개 행동 프록시를 각각 문서 내부 분포에 z-점수화해 합산. 상위 20%를 `friction_high`로. **상대 정규화라 투명**(절대 초가 아님).
5. **ICAP + 인지부하 태깅** — 단락을 P(체류만)<A(표시)<C(주석)<I(대화)로 분류하고, 고마찰+산출물(주석/대화) → **germane(생산적 분투)**, 고마찰+무흔적 → **extraneous(막힘)** 로 구분. "고마찰=다 좋음"의 함정 회피.
6. **이음새(seam) 표적 촛불** — 읽기 흐름을 깨지 않도록 **수용성 높은 순간**에만 개입: 주석 직후 / 막혀서 맴돌 때(isolation) / 세션 복귀(transition) / 막힌 단락(stuck). 주석·전환은 글로벌 쿨다운 우회(가장 신선한 순간). *근거: Hefter 2023 — 중단은 학습을 해친다.*
7. **백엔드 없는 브라우저 내 LLM** — OpenAI/Anthropic/Gemini 3사 직접 호출, 키는 사용자 보관(localStorage). 서버 인증 계층 없음(프라이버시 ↔ 검증 부재 트레이드오프). 터미널 `interpret.py`와 브라우저 `interpret.js`가 동일 출력 공유.
8. **보드 모드 + 실시간 다이제스트** — 같은 글을 3개 표현(스크롤/스프레드/보드)으로. 보드는 LLM 없이 `liveDigest()`로 마찰·ICAP를 즉시 색으로. 흔적 카드는 인터랙션 중 지워지지 않게 250ms 디바운스.
9. **포인터락 가상 커서 + 줄끝 텔레포트**(독서 모드) — OS 커서 숨기고 상대 이동으로 가상 커서. 줄 잠금 + 각도·크기 커밋으로 흔들림 방지, 줄바꿈 시 매끄러운 텔레포트.
10. **자소(grapheme) 단위 DOM + Pretext 레이아웃 캐시** — 글자마다 `<span data-char-index>`, `Intl.Segmenter("ko")`로 한글 자소 분해. 드래그 밑줄·동그라미·잉크 오버레이의 글자 단위 히트테스트 기반.
11. **CSP 안전 확장 빌드** — MV3는 원격 ESM 금지. `build-extension.sh`가 CDN import를 로컬 벤더 스텁으로 치환, 루트 소스를 단일 진실로 유지.

*(추가 디테일: 드래그 밑줄의 체인룰, 속도→불투명도 매핑, 마우스 트레일 스냅, effort_frac 멀티세션 절대지표 등은 발표에서 한두 개 보조로만.)*

### 5.3 정직성 포인트 (발표에서 **꼭** 짚을 것 — 신뢰를 만든다)
- **인용 정정의 투명성**: 코드 주석의 잘못된 인용을 직접 바로잡음 — `Luo 2017 → Brady et al. 2018`(스크롤↔이해), `D'Mello 2017 → 2014`, 근거 약한 "Socratic"은 플래그 처리. 단일 진실: `docs/theory-base.md`.
- **마찰은 절대값이 아니다**: 문서 내부 z-점수 상대값. 문서 간 단순 비교 불가(대신 `effort_frac` 사용).
- **휴리스틱 미보정**: z-점수 가중치, 임계(원형성 0.35, reverse_rate 0.5, 주석 품질 0.55, stuck 45초 등) 모두 1차 추정 — 실제 로그로 보정 예정.
- **주석 품질은 행동 프록시일 뿐**(의미 NLP 아님), **막힘 감지는 거칠다**(45초 체류 ≠ 반드시 분투), **고마찰 분류는 산출물 의존**(조용히 헤매는 독자는 수동 체류로 보임).
- **Phase 3 보류**: 멀티기기 동기화/DB, 관심 의미 교차맵(임베딩), 배치 AI 개념맵.

## 6. 톤 & 제약 (Codex 준수 사항)
- 한국어, 발표체. 청중에 비전문가 포함 → 전문 용어는 첫 등장 시 한 번 풀어 설명.
- **3축 균형**: 한 비트에 UX/기술/사고흐름이 몰리지 않게 분산.
- **코드에 있는 것만**: 위 §2 동작/§4 메커니즘 범위 내에서만 시연·주장. 없는 기능 지어내지 말 것.
- **과장 금지**: 마찰=상대값, LLM=사용자 키 의존, 휴리스틱=미보정임을 흐리지 말 것.
- 데모가 실패할 때의 **백업 멘트**(예: 촛불이 안 뜨면 `데모 리셋` 후 재시도, 또는 보드/대시보드 정적 상태로 설명)를 각 라이브 비트에 한 줄씩 곁들일 것.
