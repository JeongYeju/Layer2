## 현재 임시 결정

### 1. 기능 파트의 상위 구조는 `전 / 중 / 후`로 간다

이유:

- `신호 분석 / 촛불 / 거울`은 시스템 기능 구조다.
- `씨름 / 흔적 / 거울`은 발표의 개념 프레임이다.
- 두 구조가 서로 비슷하지만 레벨이 달라서, 나란히 쓰면 청중에게 혼동을 줄 수 있다.
- `전 / 중 / 후`는 독자가 경험하는 시간 구조라 더 직관적이다.
- 특히 `후`가 끝이 아니라 다시 다음 독서의 `전`으로 돌아가는 순환 구조를 만들 수 있다.

임시 정리:

| 시간 구조 | 독자 경험 | 들어갈 기능 |
|---|---|---|
| 읽기 전 | 이전 흔적이 다음 독서의 조건이 됨 | 누적 리포트, 시간대/주제/마찰 기반 추천, 이전 세션 복귀 |
| 읽기 중 | 글과 씨름하고 흔적을 남김 | 신호 수집, 마찰 해석, 촛불 개입, 티키타카, 뷰어/보드 전환 |
| 읽기 후 | 흔적을 되비추고 다음 읽기로 넘김 | Mental Model Map, 독서 후 티키타카, 다회독 리포트, 재독 Diff |

### B. `씨름 / 흔적 / 거울`과 `전 / 중 / 후`의 관계

상태: 의논 필요.

현재 가설:

- `씨름 / 흔적 / 거울`은 Layer 2의 철학/개념 프레임.
- `전 / 중 / 후`는 기능 설명의 시간 프레임.

### C. 0602 회의록 기반 `전 / 중 / 후` 원의도

상태: 원문 확인됨, 정리 필요.

회의록에서 확인된 흐름:

- 첫 독서/1회독에서 독서 중 개입이 일어난다.
- 독서가 끝난 뒤 집중/마찰/상호작용 흔적이 리포트, 대시보드, 트래커 형태로 포장될 수 있다.
- 독서 후 산출물이 다시 다음 읽기의 출발점이 된다.

질문:

- `읽기 전`은 독서 시작 전 추천/큐레이션인가, 아니면 이전 세션이 다음 세션을 준비하는 지점인가.
- 최종 발표에서 `전`을 너무 크게 주장하면 아직 구현 안 된 비전처럼 보일 위험이 있는지.

### D. 마지막 프레이밍

상태: 의논 필요.

사용자 희망 방향:

> AI가 읽을 수 없던 것을 읽게 됐을 때 어떤 가능성이 생기는가?
> 그리고 디자이너로서 무엇을 읽게 해야 하는가?

질문:

- 이 질문을 마지막 한 장의 문장으로 둘지, Future 이전의 비전 장으로 둘지.
- `AI가 텍스트를 읽는다`가 아니라 `AI가 독서의 흔적을 읽는다`로 정확히 고정할지.
- 디자이너의 역할을 `무엇을 자동화할까`가 아니라 `무엇을 읽을 가치 있는 신호로 만들까`로 말할지.
