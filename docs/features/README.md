# Layer 2 — 기능 문서 (Feature Docs)

이 폴더는 Layer 2 의 각 기능을 **"왜 생겼고, 어떻게 작동하는가"** 관점에서 기록합니다.
케이스 스터디·발표·인수인계에서 그대로 인용할 수 있도록, 한 기능당 한 문서로 관리합니다.

> Layer 2 가 뭔지 모르는 사람도 위에서부터 읽으면 이해되고, 코드를 만질 개발자는 끝까지 읽으면 구현까지 닿도록 — **추상 → 구체** 순서로 씁니다.

---

## 이 문서들이 채우는 빈틈

Layer 2 의 자료는 세 층으로 나뉩니다. 가운데가 비어 있었습니다.

| 층 | 어디에 | 무엇 |
|---|---|---|
| **왜 (의사결정)** | `Private/*.md` (회의록·디벨롭) | 컨셉이 어떻게 정해졌나. 비공개(gitignore). |
| **★ 기능 (이 폴더)** | `docs/features/*.md` | 결정이 *어떤 기능*이 됐고, 그게 *어떻게 도는가*. |
| **어떻게 (코드)** | 루트 `*.js` | 실제 구현. |

`Private/` 회의록은 맥락이 풍부하지만 비공개이고 서사 위주, 코드는 정확하지만 외부인이 못 읽습니다.
**이 폴더가 그 사이를 잇는 공개용 다리**입니다.

## 작성 규칙

1. **새 기능 = `_TEMPLATE.md` 복사** → `docs/features/<기능명>.md` 로 저장.
2. 8개 고정 섹션을 유지합니다 (순서도 유지 — 추상→구체가 깨지면 외부인이 길을 잃음):
   1. 한 줄 요약 · 2. 왜 생겼나 · 3. 사용자가 보는 것 · 4. 작동 원리(기술) · 5. 데이터(신호 in/out) · 6. 설계 근거 · 7. 현재 상태 & 한계 · 8. 관련 파일 / 더 읽기
3. **언어** — 한국어 메인, 기술 용어는 영어 병기 (`마찰 계수(friction)`). 청중이 한국어 발표/심사 + 개발자 둘 다라서.
4. **코드와 어긋나면 문서가 틀린 것** — 임계값·함수명·신호명은 실제 코드 기준으로 적고, 코드가 바뀌면 문서도 같은 커밋에서 갱신.
5. **근거를 끊지 말 것** — "왜 이 숫자/이 설계인가"는 회의록(`Private/`)이나 문헌으로 출처를 남깁니다. 추정값은 "추정값, 튜닝 필요"라고 명시.
6. 이 기능이 발화/구독하는 **신호(signal) 이름**을 §5 에 반드시 적습니다 — 모듈 간 결합의 유일한 공개 계약이라서.

## 청중 (이 문서를 읽는 두 사람)

- **외부인** (교수·심사위원·처음 보는 사람) — §1~§3 만 읽어도 "이게 뭐고 왜 중요한지" 이해되어야 함.
- **개발자** (미래의 나, 협업자) — §4~§8 로 구현·결합·한계까지 닿아야 함.
